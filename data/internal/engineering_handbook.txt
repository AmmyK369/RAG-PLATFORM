Amara Tech | Engineering Handbook
Document ID: ENG-HBK-021 | Version: 3.0 | Effective: 3 November 2026
Access: engineer, admin

Amara Tech engineering teams use Python 3.12 for backend services and TypeScript 5 for web applications unless an approved project exception is recorded. New services must expose versioned REST endpoints under /api/v1, validate request payloads with Pydantic or an equivalent schema library, and return consistent error objects containing a machine-readable code and a safe message. Every pull request requires one reviewer who is not the author, passing unit tests, and a linked issue in Linear. The default branch is protected; direct pushes to main are disabled. The engineering quality target is at least 80% line coverage for newly added business logic, with security-critical modules reviewed separately by the platform team.

Production deployments are scheduled Tuesday through Thursday between 10:00 a.m. and 3:00 p.m. IST. Changes outside that window require approval from Engineering Manager Farhan Ali and an on-call engineer. The standard rollback objective is 15 minutes from detection of a release-related incident. Service owners must publish a runbook covering health checks, dependencies, alert thresholds, and rollback steps before launch. Logs must include a request ID and must not contain passwords, access tokens, or customer payment details. Engineers rotate primary on-call duty weekly; the schedule is maintained by SRE Lead Meera Nair. Critical incidents are acknowledged within 10 minutes and recorded in the incident channel. Administrators may manage repository membership and build-system permissions, but code approval remains with designated engineering reviewers. The handbook owner is VP Engineering Sameer Khanna.
